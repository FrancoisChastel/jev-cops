# Decisions

Choices made while building that the spec leaves open **and** that are not in the
spec's "Open decisions" list (those are asked, not decided). Each entry names the
safer option taken and why. Reverse any of them by editing the code and this file.

| ID | Date | Decision | Why it is the safer option |
|---|---|---|---|
| D-001 | 2026-09-29 | License: Apache-2.0 | Explicit patent grant and contribution terms; standard for security tooling. Swap to MIT is a one-file change if preferred. |
| D-002 | 2026-09-29 | ~~Noul `confidence` is derived as `abs(2p − 1)`~~ **Superseded by D-038.** | The TypeSafe SDK (`@typesafe-ai/sdk@0.6.0`) returns `{ noul: p }` with no confidence field. The derivation double-counted uncertainty: it discarded p ∈ (0.25, 0.75) and made the spec's own example unable to deny above p = 0.1. |
| D-003 | 2026-09-29 | `$HOME`/`~` expansion uses a `home` value from daemon config (default `os.homedir()` of the daemon host), never from the event | The event schema has no home field and adapters must not add one; trusting an agent-supplied home would let it steer path normalization. |
| D-004 | 2026-09-29 | Semantic judge is provider-pluggable behind one `Judge` interface: `mock`, `jev`, `openrouter`, `vercel-ai` | Requested by the owner mid-build (spec extension). Core and policies depend only on the interface; the monotonic floor, confidence routing, timeout and cache rules apply identically to every provider. LLM providers answer the same typed questions via structured output; their self-reported confidence is treated exactly like Jev's, and the deterministic floor is what limits damage from a badly calibrated provider. |
| D-005 | 2026-09-29 | Parse failures in the bash normalizer never throw; the whole command becomes one `opaque` span with `reason: "parse-error"` and `kind: "exec"` | An unparseable command must be scored like an unknown exec, not skipped. |
| D-006 | 2026-09-29 | Spec repo layout kept; the spec itself lives at `docs/SPEC.md` | The handoff file was dropped at the repo root; the spec's own layout section names `docs/`. |
| D-007 | 2026-09-29 | Bun is pinned via `packageManager` and CI; Node is not a supported runtime for the daemon | `bun:sqlite` and `bun build --compile` are hard dependencies per the spec's tech choices. |
| D-008 | 2026-09-29 | Headless `hold` (and `hold` on harnesses with no "ask", i.e. Pi) maps to `deny` with the verdict's `reason` | Owner decision from spec §Open decisions. A pause the harness cannot honour must not become an allow. |
| D-009 | 2026-09-29 | Pilot uses the spec's default thresholds: budget 100, decay 10/min, bands 0.3 / 0.5 / 0.8 | Owner decision from spec §Open decisions. Values live in one config module so a team override is a single edit. |
| D-010 | 2026-09-29 | Event schema is strict at every nesting level; only `call.input` accepts arbitrary keys, and it is returned as the same object reference (no zod `record`, which drops `__proto__`) | The daemon never accepts shapes it does not understand; `input` must be verbatim so the normalizer sees exactly what the harness will run. |
| D-011 | 2026-09-29 | `id` must be `evt_` + an upper-case 26-char ULID with first char 0–7; `session.id` / `call.id` / `parent_id` are `sess_`/`call_` + non-whitespace | Tight formats make forged or sloppy ids fail fast at the adapter boundary. |
| D-012 | 2026-09-29 | Verdict response: `updated_input` must be non-null iff `verdict === "rewrite"`; `detail` is optional; `stdout_head` 4 KB bound is documented but not enforced by the schema (adapter responsibility) | A rewrite without a payload or a payload without a rewrite is a bug; `detail` may be stripped before the response reaches an adapter. |
| D-013 | 2026-09-29 | Normalized event `kind` order: `exec` if any command is opaque or an interpreter; else `fs.delete` > `net` > `fs.write` > `spawn` > plain exec > `fs.read` > `other`. `event.call.kind` (the adapter's mapping) is kept untouched alongside | The daemon's own classification may be stricter than the adapter's; side effects outrank an unknown binary so `cd . && curl -d @.env …` reads as `net`. |
| D-014 | 2026-09-29 | Any `$VAR`/`${…}`/`$((…))` other than `$HOME`/`~` is `dynamic-expansion` (opaque), quoted or not; the word stays verbatim in argv | The value is unknown at judge time (T9); only HOME comes from daemon config (D-003). |
| D-015 | 2026-09-29 | Wrappers `env nohup setsid sudo doas timeout xargs` add the `interpreter` flag; `command exec builtin nice time stdbuf` are unwrapped silently. Shells always count as interpreters; python/node/perl/ruby/php only with inline code or stdin. `git -c` command-valued config, `awk system()/getline`, sed `e` flag also count as interpreters | Found by adversarial review of the normalizer; each is a shell-out path that would otherwise look like a plain read. |
| D-016 | 2026-09-29 | `stateHash` covers argv, kinds, verbs, targets, per-command env, redirects, heredoc bodies and the full input of non-Bash tools; excludes ids, timestamps, opaque spans and agent-written descriptions | Without heredoc bodies and tool input, a benign and a malicious Edit to the same file would share a judge-cache key (cache poisoning). |
| D-017 | 2026-09-29 | Literal `cd`/`pushd` update the cwd for following commands (subshell scoping not tracked); `/dev/null`, `/dev/std*`, fd duplication are not paths; `/dev/tcp|udp/host/port` redirects are `net` | Path resolution must follow the shell's own cwd; `/dev/tcp` is a well-known exfil channel that is not a file. |
| D-018 | 2026-09-29 | Decoding: hex wins over base64 when a word is valid in both; paths and options are never decoded; only the first 64 KB of a word is decoded (not skipped); literal `echo`/`printf` output piped into a shell is parsed as code | Padding past a size cap must not dodge decoding; the unencoded echo-pipe is the same T5 shape. |
| D-019 | 2026-09-29 | Fail-closed normalization: any throw, stack overflow or pathological nesting yields one `exec` command with `parse-error`; `raw` falls back to `"[unrenderable tool input]"` | Spec D-005 extended to cover walker failures, not just parser errors. |
| D-020 | 2026-09-29 | Secret glob `**/.env*` is implemented as `**/.env{,.*,-*,_*,rc}`, case-insensitive; `~/.ssh/**` and `~/.aws/**` also match the directory itself | `.environment.md` must not be a secret; `cp -r ~/.ssh` must count as a read. |
| D-021 | 2026-09-29 | Taint: tool output registers at the source's own taint; a write's taint is the max of the event's taint, tainted strings in the written content and any tainted self-written file the command reads; a token naming a tainted self-written file is itself tainted; strings equal to cwd, repo root, home or their parents are never taint | T10 laundering must propagate through copies and reads; a `pwd` output must not taint every path under the repo. |
| D-022 | 2026-09-29 | Secret reads are recorded at `pre` (intent), and a call's own `@.env` read counts toward the secret-then-net patterns; "seen before" excludes the judged call | The judge must see the secret access in the same event that exfiltrates it, and `computeFeatures` must be callable before or after `recordPre`. |
| D-023 | 2026-09-29 | Budget decays per whole minute of inactivity; `chargeHold` is a surcharge on top of `charge` making the nth repeated hold cost base × 2ⁿ (capped at the limit); reset keeps hold counts | Partial-minute decay would let a trickle of small steps stay free; hold counts must survive a reset or T7 farming resets them. |
| D-024 | 2026-09-29 | Environment: unknown repo counts as cwd-outside-repo; missing sandbox counts as `none`; without `default_branch`, `main`/`master` are default; host class is the max over targets, `dev` weighs 0 | Missing information is treated as exposure, never as safety. |
| D-025 | 2026-09-29 | Scope is deterministic-only and reads `cf.task`, never the event's task (T11); git remote host comes from `repoHints.remoteHost` supplied by the daemon; opaque calls contribute 0.7 and unexpected tools 0.5, both marked `unsure` | The event schema carries no remote; only the immutable case-file task may define scope. |
| D-026 | 2026-09-29 | Reversibility: a write under the repo is reversible (tracking unknowable without FS); any `force`/`hard`/`irreversible`/`privilege` verb, net write, or delete/write outside repo and `/tmp` is 1; unknown HTTP method counts as a write; unknown/MCP tools with no parsed commands score 0.5 | Follows the spec's "treat `other` like exec". Note: this makes in-repo `rm -f` score 1; revisit when policies land. |
| D-027 | 2026-09-29 | A replayed or late `pre` for a known call id never overwrites the stored record; it is logged as an anomaly. Host first-contact is read from `hostsFirstSeen()` | Found in review: overwriting let an agent pre-seed a host and hide a later first contact. |
| D-028 | 2026-09-29 | Floor risk = clamp01(0.35·taint + 0.25·(1−scope) + 0.20·sequence + 0.10·environment + 0.10·reversibility), rounded to 9 decimals; NaN features count at their risky end. Bands: ≥ 0.3 annotate, ≥ 0.5 hold, > 0.8 deny, NaN → deny; bands never produce `rewrite` or `kill` | The plan's proposal, now implemented. Rounding stops float drift (0.49999999999999994) from landing on the wrong side of a band. |
| D-029 | 2026-09-29 | Questions are asked only when floor ∈ [0.3, 0.8] inclusive. Confidence < 0.5 discards the answer; 0.5–0.8 inclusive caps that policy at `hold`; > 0.8 used as is. Losing any one answer makes the whole policy take `fallback ?? bandVerdict(floor)`. The cap wins over a declared range minimum | Spec rules 1 and 3 with the boundaries pinned. |
| D-030 | 2026-09-29 | A `decide` that throws or returns a non-verdict → `max(fallback ?? band, "hold")`. A `when` that throws, returns a non-boolean or exceeds 2 ms counts as matched and is traced; third overrun in a session marks the policy `degraded` | A broken policy must fail toward asking a human, never toward allowing. |
| D-031 | 2026-09-29 | Batch of ≤ 4 questions per event, named `policy/name`; policies take slots in load order and a policy whose questions do not fit is skipped whole (floor stands); the engine's own `jev-cops:serves_task` scope question goes last, only when scope is unsure, floor in band, task known and a slot free | Spec rule 5 with a deterministic allocation. |
| D-032 | 2026-09-29 | Judge cache key = stateHash + case-file task + hash of the sorted questions; only validated successes are cached; the judge never sees the input keys `description`, `prompt`, `explanation`, `reason`, `rationale`, `justification`, and the task comes from the case file | Answers must not be reused across tasks; T6/T8: the agent's own prose never reaches the judge. |
| D-033 | 2026-09-29 | `PolicyEvent.call.kind` is the daemon's normalized kind; the adapter's is `call.adapterKind`; `session.task` is the case-file task | Otherwise the spec example `e.call.kind === "net"` never matches a `curl` run through Bash. |
| D-034 | 2026-09-29 | Budget: at ≥ 80 % every verdict rises one step (annotate → rewrite → no payload → hold); at 100 % any kind other than `fs.read` is at least `hold`. A final `hold` also charges the repeat surcharge keyed by kind + sorted verbs (arguments excluded) | "Non-trivial" pinned to anything that is not a read; a coarse hold key defeats T7 farming by argument variation. |
| D-035 | 2026-09-29 | Precedents lower risk by at most 0.3, waive only the non-deny verdicts of the policies they name, are ignored entirely when any policy says `kill`, and may lower a floor-band deny (a human decision, not a model one) | Spec §Precedents; the floor-deny guard is for model answers only. |
| D-036 | 2026-09-29 | A final `rewrite` needs exactly one distinct `updated_input` (canonical JSON); none or conflicting payloads → `hold` with a flag | A rewrite without a payload must never run the original input. |
| D-037 | 2026-09-29 | Loader: `.ts/.js/.mjs`, non-recursive, file-name order, skips `*.test.*`/`*.d.ts`, higher version wins on duplicate names (earlier file on tie), async `when` rejected, policies frozen | Deterministic load order makes question-slot allocation (D-031) reproducible. |
| D-038 | 2026-09-29 | A noul answer from a provider that reports no confidence (Jev) is used as is: confidence 1 for p ∈ [0, 1], 0 (discarded) for NaN or out of range. Providers that self-report a noul confidence (LLM providers) still go through confidence routing | Replaces D-002. A calibrated `p` already carries the uncertainty; policy thresholds act on `p` directly. For the exfil policy this is strictly stricter (p = 0.2 → deny instead of hold; p = 0.5 → hold instead of annotate). The floor −0.2 cap still bounds any lowering. |
| D-039 | 2026-09-29 | `exfil-after-secrets` declares `fallback: "hold"`; a matched policy whose questions are unanswered lands on its fallback rather than the floor band | With the judge off, a POST to an unknown host right after reading `.env` would otherwise only annotate. |
| D-040 | 2026-09-29 | `/private/tmp` is scratch space alongside `/tmp` (core `scope.tmpDirs`; `off-repo-write` treats paths strictly *under* them as scratch, `/tmp` itself is not) | macOS resolves `/tmp` to `/private/tmp`; deleting the temp dir itself is not scratch work. |
| D-041 | 2026-09-29 | Fixture runner: fixed clock from 2026-09-29T09:12:00Z stepping `stepMs` (default 1 s) per event, `home` pinned to `/home/dev`, `when` budget 50 ms (an overrun counts as matched, so a cold call would make allow fixtures flaky), engine scope question off unless the case records an answer for it, `describeFixtures` exported from `@jev-cops/sdk/test` so loading a policy never imports `bun:test` | Fixtures must be deterministic and machine-independent. |
| D-042 | 2026-09-29 | Providers never retry (`maxRetries: 0`); the core `withTimeout` guard owns the 10 s budget. | D-043 | 2026-09-29 | Jev client is pinned to config: `TYPESAFE_BASE_URL`/`TYPESAFE_DEFAULT_MODEL` env are ignored, SDK logging is off, and a model-id string is not accepted for `vercel-ai` (only a `LanguageModel` instance) | T13: the endpoint command text goes to is chosen by the daemon's config, never by the environment the agent may influence, and never routed through a global gateway by accident. |
| D-044 | 2026-09-29 | A missing API key yields a judge that answers `disabled` with a clear detail; the factory never throws and never calls `fetch`. Keys are redacted from every error detail | The daemon must run observe-only without keys. |
| D-045 | 2026-09-29 | LLM providers: constant system text pinning the classifier role (T6), state and questions as fenced JSON with a fence longer than any backtick run in the content, one closed JSON Schema per batch with every property required and bounded; probabilities must sum to 1 ± 0.1 and are rescaled; a Jev response body is validated as untrusted input | Injected instructions travel only as data; a malformed or partial answer is `invalid`, never a guess. |
| D-046 | 2026-09-29 | Error classification for all providers: abort/timeout → `timeout`; connection failure, 408, 429, 5xx → `unreachable`; 401/403 and other 4xx, malformed body, schema failure → `invalid` | Every error kind makes the floor stand (spec rule 4); the kinds only steer `doctor`/audit messages. |
| D-047 | 2026-09-29 | Daemon `enforcement.mode` defaults to `observe`: every verdict is judged and logged, the harness receives `allow`, and for `hold`/`deny`/`kill` a `context_note` says what jev-cops would have done. `enforce` returns verdicts as is.
